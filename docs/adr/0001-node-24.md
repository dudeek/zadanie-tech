# 0001. Node 24 lokalnie, w CI i na Vercelu

- Status: przyjęta
- Data: 2026-10-22

## Kontekst

Nuxt 4.6 wymaga Node `^22.22.3 || ^24.15.0 || >=26.0.0`. Vercel obsługuje najwyżej Node 24.x.
CI ze startera używa Node 24. Lokalnie (mise, globalnie) był Node 26. Bez przypięcia wersji
dev i produkcja działają na różnych wersjach, a błędy zależne od wersji wychodzą dopiero po deployu.

## Rozważane opcje

1. Node 24 wszędzie: `mise.toml` + `engines.node` w `package.json`.
2. Lokalnie Node 26, `engines` jako zakres zgodny z Nuxtem (Vercel i tak wybierze 24).
3. Tylko `mise.toml`; wersja na Vercelu z ustawień projektu w dashboardzie.

## Decyzja

Opcja 1. `mise.toml` przypina Node 24 i pnpm 12.14.0, `engines.node: "^24.15.0"`.
Vercel czyta `engines` i nadpisuje nim ustawienia projektu, więc wersja jest w repo, a nie w dashboardzie.
Dolna granica 24.15.0 to minimum Nuxta dla linii 24.

## Minusy

- Lokalnie rezygnujemy z Node 26.
- Wersja pnpm jest w dwóch miejscach (`mise.toml` i `packageManager`), trzeba je zmieniać razem.

## Warunek rewizji

Vercel udostępni Node 26 albo Nuxt przestanie wspierać linię 24.
